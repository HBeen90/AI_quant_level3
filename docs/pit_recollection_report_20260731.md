# PIT 판정원장 독립 재수집 대조 보고 — L09 승격

- 수행일: 2026-07-31
- 수행: 김소연 (파트4) · 절차적 독립
- 도구: `analysis/recollect_pit_evidence.py`
- 증거: `evidence/recollect_20260731/`
- 판정: `L09_PARTIAL` → **`METADATA_VERIFIED`**

---

## 1. 왜 했는가

원장이 **형식상 완성**된 것과 그 근거가 **원문에서 재확인**된 것은 다른 사실이다.
`FINAL_INPUT_CONTRACT`는 2026-07-29에 완료됐으나 계보 등급은 `L09_PARTIAL`로
남아 있었고, 종결 기록이 그 이유를 명시했다 — DART 원문 215건의 독립 재수집
대조가 `METADATA_VERIFIED` 승격의 필수 조건이다.

미룰 수 없었던 직접적 근거가 하나 있다. 2026-07-30 표적 추인에서 **6건 중
1건**(오로스테크놀로지 FY2024·FY2025)이 원문 HBM 언급 0회로 확인돼 원장 판정이
정정됐다. 나머지 209건에 같은 것이 없다는 근거는 없었고, 발견이 늦을수록
대응 비용이 커진다(원장 정정 → 스냅샷 재생성 → 백테스트 재실행 → FACTSHEET
재생성 연쇄).

## 2. 독립성을 어떻게 지켰는가

수집하면서 대조하면 기존 값에 맞춰 고르게 되고, 그 순간 순환검증이 되어
아무것도 증명하지 못한다. 그래서 세 단계를 **명령으로 분리**했다.

| 단계 | 명령 | 입력 |
|---|---|---|
| 1 | `--scope` | 원장에서 `ticker`·`name`·`fiscal_year` **세 컬럼만** (`usecols` 강제) |
| 2 | `--collect` | `scope.csv` 만. 원장 파일을 열지 않음 |
| 3 | `--crosscheck` | 2단계 동결이 끝난 뒤에만 원장과 대조 |

판정값·접수번호·접수일은 2단계까지 한 번도 로드되지 않는다.

**한계 고지.** 이는 제3자 검증이 아니라 **절차적으로 분리된 재수집**이다.
수행자가 원장 작성 맥락을 알고 있다는 사실은 변하지 않으므로, "제3자가
독립 재수집했다"고 표현하지 않는다.

## 3. 무엇을 대조했는가

접수번호(`rcept_no`) · 접수일(`rcept_dt`) · 보고서명(원본/정정본 선택) ·
원문 SHA-256이다. **매출 노출도·메모리향 비중 등 내용 판정값은 재판정하지
않았다** — 파트2 책임이며, 이 대조의 범위가 아니다.

다만 원문의 HBM 언급 횟수를 함께 세어, 판정과 원문이 어긋나는 행을 사람이
볼 수 있도록 표시했다.

보고서 선택 규칙은 원장 작성 당시와 동일하게 적용했다.

> `kind=A` · `final=False`(원본·정정본 모두 조회) · 보고서명에 「사업보고서」
> 포함 · 정정본 제외 후 접수일·접수번호 오름차순 최초 1건

## 4. 결과

```
수집  : 215건 · 상태 OK 215 · 조회 실패 0
대조  : MATCH 213 · MATCH_RCPNO_DATE 2
        MISMATCH 0 · NOT_COLLECTED 0 · ONLY_LEDGER 0 · ONLY_RECOLLECT 0
```

**`MISMATCH` 0건**이 핵심이다. 215건 중 원장과 다른 보고서를 고른 건이 하나도
없다. 선택 규칙이 독립적으로 재현됐다는 뜻이다.

### 4-1. 접수일 표기 상이 2건 — 문서 결함 발견

`rcept_dt` 필드와 접수번호 내장일이 실제로 다른 행이 2건 있었다.

| 종목 | 사업연도 | `rcept_dt` | `rcpNo` 내장일 | 원장 `disclosed_at` |
|---|---|---|---|---|
| 한솔케미칼 014680 | 2020 | 2021-03-17 | 2021-03-16 | 2021-03-16 |
| 하나마이크론 067310 | 2022 | 2023-03-28 | 2023-03-27 | 2023-03-27 |

이 2건이 **문서 결함 하나를 드러냈다.** 종결 기록 §4는 규칙을
`DART rcept_dt 채택`이라고 적었으나, 실제로 채택된 값은 접수번호 내장일이다.
215건 중 213건은 두 날짜가 같아 드러나지 않았고, 어긋나는 2건에서만 노출됐다.

**원장이 아니라 서술을 정정했다.** 접수번호가 접수 시점의 직접 증거이므로
정본으로 유지하고, 종결 기록 §4의 문구만 고쳤다. 두 날짜의 차이가 어떤
심사기준일(5월·11월 말)도 가르지 않아 편입 판정·스냅샷·백테스트 결과에
영향이 없다.

방향성은 기록해 둔다. 접수번호 내장일은 `rcept_dt`보다 **이른** 날짜이며,
PIT 관점에서 보수적인 선택은 늦은 날짜다. 이번 표본에서는 영향이 없었으나
규칙을 조문화할 때 위원회가 이 방향성을 인지하고 확정해야 한다.

### 4-2. 원문 HBM 언급 0회 2건 — 신규 발견 없음

| 종목 | 사업연도 | `hbm_exposure` | 원문 HBM 언급 |
|---|---|---|---|
| 오로스테크놀로지 322310 | 2024 | 0.02 | 0회 |
| 오로스테크놀로지 322310 | 2025 | 0.03 | 0회 |

**표적 추인에서 이미 확인·정정된 바로 그 2건**이다. 209건을 새로 조사했으나
같은 유형의 **신규 발견은 0건**이었다. 표적 추인 이후 열려 있던
"나머지에도 있을 수 있다"는 위험이 닫혔다.

이 2건의 판정 유지 근거는 `docs/judgment_record_322310_atsemicon_20260730.md`와
`docs/decision_package_322310_20260730.md`에 있으며, 본 재수집은 그 기록이
원문과 일치함을 확인한 것이다.

## 5. 승격

`evidence/source_docs/final_ledger_manifest.json`

```
lineage_level                    : L09_PARTIAL      -> METADATA_VERIFIED
independent_recollection.status  : PENDING          -> DONE
```

`verify_claims.py`의 인용 금지 항목에서 `DART 215건 독립 재수집 대조 완료 주장`을
해제하고, 재현 클레임 `c_pit_recollection`을 등록했다. 알려진 예외 4건은
목록으로 고정했으므로 **새 예외가 생기면 즉시 FAIL** 한다 — 그래야 이 검증이
다음 회차에도 의미를 갖는다.

## 6. 이제 쓸 수 있는 문장 / 여전히 쓸 수 없는 문장

**쓸 수 있다**

- "DART 원문 215건을 독립 재수집해 원장 근거와 전수 대조했고 불일치 0건이었다."
- "접수번호·접수일·보고서명·원문 해시가 모두 재현됐다."
- "판정원장 계보는 `METADATA_VERIFIED` 다."

**쓸 수 없다**

- "제3자가 독립 재수집했다" — 절차적 분리이지 제3자 검증이 아니다.
- "판정값까지 검증했다" — 내용 판정은 대조 범위 밖이다.
- "오로스 2건이 이번에 발견됐다" — 표적 추인에서 이미 확인된 건이다.

## 7. 재현

```powershell
python analysis\recollect_pit_evidence.py --scope
python analysis\recollect_pit_evidence.py --collect
python analysis\recollect_pit_evidence.py --crosscheck
python analysis\verify_claims.py --fast
```

`--collect`는 DART OpenAPI 키가 필요하며 215건 조회에 10~30분이 걸린다.
10건마다 저장하므로 중단 시 같은 명령으로 이어받는다.
