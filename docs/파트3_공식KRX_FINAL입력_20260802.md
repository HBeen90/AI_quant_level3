# 파트3 작업 내역 - 2026-08-02

## 1. 결론

FINAL 백테스트의 시장 데이터 입력을 공식 KRX 전종목 시세 13회차로 고정했다.
다운로드 파일의 조회일자 부재 문제는 KIS 원주가와의 33종목 종가 대조로 해결했고,
매핑 결과와 원본 SHA-256을 저장했다. 공식 입력으로 재생성한 13개 PIT 스냅샷은
기존 스냅샷의 구성 판정과 유동시가총액 값에 변화가 없다.

## 2. 채택한 데이터 계보

| 항목 | 정본 | 용도 |
|---|---|---|
| 시장 시가총액·종가·전종목 순위 | KRX 전종목 시세 13개 원본 | 심사일 시장 팩트 |
| ADV60 | KIS 일별 거래대금 패널 | 심사일 포함 직전 60거래일 평균 |
| 상장일 | KRX 전종목 기본정보 | 상장 3개월 요건 |
| 유동비율 | FINAL 판정원장 | KRX 시가총액에 곱해 유동시가총액 산출 |
| 지수 수익률 가격 | KIS 수정주가 캐시 | PR 지수 일별 수익률 |

`data/price_cache_manifest.json`은 FINAL에서 쓰는 `out/px.csv`의 KIS 원천,
수정주가 여부, 관측 기간, 행·종목 수, SHA-256을 고정한다. FINAL 스크립트는
가격 캐시 해시·종료일·`adjusted_close` 유형 중 하나라도 매니페스트·D1 계약과
다르면 실행을 중단한다.

KIS 수집 원본은 CRLF 해시 `07F800B0...`, Git 동결본은 `.gitattributes`에 맞춘
LF 해시 `FED83F01...`로 구분해 기록했다. 따라서 커밋의 줄바꿈 정규화가 캐시
계보를 조용히 깨뜨리지 않는다.

벤치마크 KRX 반도체 PR(5044)은 첫 FINAL 실행에서
`out/benchmark_5044_pr_20200615_20260723.csv`로 저장한다. 같은 실행에서 LF로
정규화하고 FINAL 매니페스트 입력 해시와 release 커밋에 포함하므로, 그다음
재현부터는 KRX 네트워크가 없어도 동결 캐시를 사용한다. 최초 한 번은 코드-이름
대조와 시계열 수집을 위해 KRX 접속이 필요하다.

`data/market_facts/source_mapping.csv`는 원래 다운로드 파일명, 심사일,
33종목 종가 일치 건수, 차순위 일치 건수, 원본 SHA-256, 정본 복사 파일명을 보존한다.
13개 파일 모두 해당 심사일에서 비교 가능한 종목의 종가가 100% 일치했고,
차순위 날짜와 명확히 분리됐다. 날짜 판별에 사용한 KIS 원주가 패널의 파일명과
SHA-256도 함께 기록해 어떤 가격 빈티지로 매핑했는지 고정했다.

각 `facts_YYYYMMDD.csv`는 다음 계보를 함께 가진다.

- `asof`
- `market_cap_source`
- `source_file`
- `source_sha256`

`build_pit_snapshots.py --market-facts-dir`는 facts 파일뿐 아니라
`source_mapping.csv`와 `raw/` 원본의 SHA-256까지 대조한다. 원본·매핑·facts 중
하나라도 바뀌면 스냅샷 생성을 중단한다.

## 3. 교차검증 결과

- KRX 전종목 시세 13개를 심사일 13개에 중복 없이 매핑했다.
- 기존 스냅샷과 유효 비교 가능한 유동시가총액 397건이 허용오차 `1e-6` 안에서 모두 일치했다.
- 새 공식 스냅샷과 기존 스냅샷의 `ticker`, `eligible`, `group`, `float_mcap`,
  `selection_date`, `ff_market_cap_asof`, `free_float_asof`가 13회차 모두 일치했다.
- 전구간 이벤트 원장, 구성 변경 이력, 회전율은 기존 실행과 동일하게 재현됐다.
- `INDEX_ASOF=2026-07-23` 고정 여부는 결과값에는 영향을 주지 않았고,
  실행 범위 표기만 `2026-07-23`으로 재현 가능하게 고정했다.

성과 수치는 FINAL 게이트 실행 전까지 `verify_claims.py`의 인용 금지 규칙을 따른다.

## 4. 수정한 코드

- `analysis/match_krx_screens.py`
  - 날짜 없는 KRX 파일을 KIS 원주가로 유일 매핑한다.
  - 일치율 95% 미만, 차순위 격차 20%p 미만, 날짜 중복, 회차 누락 시 중단한다.
  - 정본 복사와 `source_mapping.csv` 생성을 함께 수행한다.
- `analysis/krx_facts_from_screen.py`
  - KRX 시가총액·종가·전종목 순위와 KIS ADV60을 결합한다.
  - ADV60은 심사일을 포함하며, 거래정지 결측은 0으로 센다.
- `analysis/build_pit_snapshots.py`
  - `--market-facts-dir` 공식 입력 경로를 추가했다.
  - facts·원본·날짜 매핑의 SHA-256과 스키마를 fail-closed로 검증한다.
  - 스냅샷에 facts·원본·매핑 해시를 기록한다.
- `run_backtest_final.ps1`
  - FINAL 실행 시 네트워크 조회 대신 동결된 `data/market_facts`를 소비한다.
  - `INDEX_ASOF`와 Git HEAD를 고정한 뒤 스냅샷을 재생성한다.
  - 빠른 FACTSHEET 정리, 전 테스트, 전체 FACTSHEET 재생성 순으로 실행해
    테스트 통과 클레임까지 최종 문서에 포함한다.
- `tests/test_backtest_manifest.py`
  - 오류 문장 전체가 아니라 `code_commit`과 `현재 HEAD`를 검사하도록 바꿔,
    표현 수정에 흔들리지 않으면서 오래된 스냅샷 차단 의미를 유지했다.
- `tests/test_claims.py`
  - FACTSHEET의 테스트 스위트 클레임이 자기 자신을 다시 호출해 실패가 고착되는
    순환을 끊었다. `verify_claims.py`의 명시적 내부 호출에서만 저장본 상태 검사를
    생략하고, 일반 테스트에서는 모든 실패 클레임을 계속 차단한다.

## 5. 데이터 오류와 폐기 경로

### 정정

`data/raw/HBM_value_33_2020Q1_2026Q1.csv`의 잘못된 `222080 SFA넥셀`
25개 분기 행을 `222800 심텍` 정본으로 교체했다. 정정본 SHA-256은
`6A321BF37D28DB661692CDF06E519F8155EFAC4EDE4BD17C52F11A941EC0D4E4`다.

### 폐기

분기말 발행주식수와 일별 주가를 조합해 심사일 시가총액을 만드는
`facts_from_shares.py` 경로는 FINAL 입력으로 사용하지 않는다. 분기 중 분할·증자 때문에
기존 공식 스냅샷과 397건 중 57건이 불일치했고 최대 상대차가 75%였다.
수정주가·원주가 어느 한쪽만 바꾸는 방식으로는 이 문제를 안전하게 해결할 수 없다.

금융위 API 경로는 네트워크 장애 시 대체 수집기로만 보류한다. 이미 확보한 공식 KRX
원본을 두고 FINAL 실행에 API 의존성을 추가하지 않는다.
