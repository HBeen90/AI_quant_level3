## 결론 먼저

화면에 뜬 성과·비중 수치는 **우리 엔진에서 재현되지 않고, 우리 조문을
위반하며, 화면끼리도 서로 맞지 않습니다.** 지금 상태로 발표하면 검산 한 번에
무너집니다.

정리해 주신 5개 항목 중 **1번의 고지 문구만으로는 부족합니다.** 고지는
"27/67 버퍼 수치"만 덮는데, 화면에는 그보다 훨씬 많은 것이 실측인 양
올라가 있습니다 — 지수 레벨 3,161.9pt, CAGR 21.6%, Sharpe 0.89,
MDD −25.4%, 벤치마크 9.3%/−34.1%, 종목별 HBM 노출도, 유동시총, ADV60.
게다가 차트 부제가 **"PIT 스냅샷 13회 정기변경 기반 실데이터 시뮬레이션"**
이라 고지와 정면으로 충돌합니다.

## [E] 가장 중요한 것 — 편출입 건수의 출처

| 정책 | 화면 편입/편출 | `demo_why_pit.py` 합성 출력 |
|---|---|---|
| none | 32 / 29 | **32 / 29** |
| narrow | 28 / 24 | **28 / 24** |
| mid | 21 / 15 | **21 / 15** |
| wide | 18 / 12 | **18 / 12** |

**4개 정책 8개 숫자가 전부 일치합니다.** 우연이 아닙니다.

그 데모의 종목은 `A00001` · `C00000` · `G00001` · `B00001` · `T00001`
같은 **가상 티커**이고, 노출도 궤적은 제가 "테마 성장기의 전형적 패턴"으로
손수 만든 예시입니다(파일 헤더에 명시). 그 위에 삼성전자·SK하이닉스·
한미반도체·디아이·테크윙·심텍·와이씨켐·솔브레인·한솔케미칼·원익IPS라는
**실제 회사명이 입혀졌습니다.**

정기변경 시행일과 종목 수(17 / 20 / 21 / 21)도 데모 출력과 같습니다.

이건 제가 계속 경고한 실패 모드가 그대로 실현된 것입니다 — 합성 결과가
전문적인 UI를 입으면 **실측처럼 보입니다.** 회전율 48.5%/24.6%와 CAGR
20.3%/21.6%는 그 합성 건수 위에 추가로 창작된 값이라 출처조차 없습니다.

## [A·B] 목표 비중이 엔진에서 재현되지 않고, 조문 상한을 위반합니다

화면의 유동시총을 `weighting.allocate`에 그대로 넣어 돌린 결과:

**2026-06-15 스냅샷**

| 종목 | 유동시총 | 화면 비중 | 엔진 재현 | 차이 | 판정 |
|---|---|---|---|---|---|
| 삼성전자 | 285.00조 | 24.00% | **25.00%** | +1.00%p | |
| SK하이닉스 | 112.00조 | 16.00% | **15.00%** | −1.00%p | |
| 한미반도체 | 7.30조 | 29.32% | **18.00%** | −11.32%p | **❌ core 상한 18% 위반** |
| 디아이 | 1.80조 | 11.24% | **17.49%** | +6.25%p | |
| ISC | 1.20조 | 8.45% | **11.66%** | +3.21%p | |
| 하나마이크론 | 0.95조 | 6.21% | **9.23%** | +3.02%p | |
| 테크윙 | 0.72조 | 4.78% | **3.61%** | −1.17%p | |

**최대 재현 오차 11.32%p.** 교차검증 리포트가 자랑하던 허용치는
**0.005%p**였습니다 — 2,264배 벗어납니다.

세 스냅샷 모두 같은 문제입니다:

| 스냅샷 | 최대 재현 오차 | 상한 위반 |
|---|---|---|
| 2026-06-15 | 11.32%p | 한미반도체 29.32% > 18% |
| 2023-06-12 | 14.10%p | 한미반도체 32.10% > 18% |
| 2020-06-15 | 16.50%p | 한미반도체 34.50% > 18% |

### 왜 이게 치명적인가

`ConfigV2.core_ind_cap = 0.18` (비앵커버킷 30% × 0.60)은 **팀이 확정한
조문**입니다. 실제 확정 인계 CSV에서도 한미반도체 비중은 **0.18**로 캡에
걸려 있습니다(`w1 = [.2157, .1843, .18, .18, ...]`). 교차검증 리포트가
"한미반도체 원배분 48.8670%p"를 상한이 흡수했다고 기록한 그 값입니다.

화면의 29~34%는 **조문도 위반하고 실제 확정본과도 다릅니다.**
"개별 상한이 쏠림을 통제한다"는 방법론의 핵심 방어 논리가 화면에서
스스로 무너져 있습니다. 심사위원이 상한을 아는 순간 끝나는 지점입니다.

앵커 24%/16%도 엔진 값(25%/15%)이 아니라 `index_calc.py` **v1 데모의
하드코딩 값**(`weights = [0.24, 0.16, ...]`)과 같습니다.

## [C] 화면 안에서 숫자끼리 안 맞습니다

| 화면 표기 | 함의값 |
|---|---|
| 카드 배지 **+218.0%** | CAGR 21.27% |
| 카드 본문 **+216.2%** (3,161.9pt) | CAGR 21.15% |
| 성과표 **CAGR 22.4% (0bp)** | 누적 **236.3%** |
| 성과표 **CAGR 21.6% (30bp)** | 누적 **223.3%** |

같은 카드 안에 **+218.0%와 +216.2%**가 동시에 있습니다. 그리고 성과표의
CAGR 두 값은 어느 쪽도 누적 218%와 맞지 않습니다 — 같은 시계열에서 나온
숫자가 아니라는 뜻입니다.

Sharpe 0.89는 무위험 1.5% 가정인데, 2020~2026 한국 기준금리 구간과
맞지 않습니다(별도 고지 필요).

**222800(심텍) 하나**뿐입니다. 탭 두 개를 나란히 여는 사람이면 바로
봅니다.

## 검증되지 않은 채 실려 있는 값들

| 화면 값 | 문제 |
|---|---|
| 삼성전자 HBM 노출도 **42%** (2026) | 삼성 전사매출 300조+의 42% = 126조. HBM 시장 전체보다 큼 |
| 삼성전자 노출도 10% → 42%, 한미 31% → 78% | DART에서 실제로 뽑은 적 없음 |
| ADV60 (삼성 6,500억 · 테크윙 45억 등) | pykrx로 수집한 적 없음 |
| KOSPI 반도체 BM +72%, MDD −34.1% | 벤치마크 지수를 조회한 적 없음 |
| 유동시총 180조 → 285조 시계열 | 2026-07-23 1회분 외에 산정한 적 없음 |

**앵커는 규칙 0(메모리제조 ∧ HBM양산)으로 판정하고 노출도를 보지 않습니다.**
그래서 삼성전자 노출도 42%는 판정에 쓰이지도 않으면서 "실측처럼 보이는"
숫자만 화면에 남아 있습니다 — 방어할 수 없는데 공격받기는 쉬운 조합입니다.

## 지금 할 수 있는 세 가지

### A. 성과 화면을 내리고 설계 화면만 남긴다 (30분, 가장 안전)

파이프라인 상태 · PIT 규율 데모 · 용량 역산기 · 조문 구현 현황만 남깁니다.
**이것만으로도 발표는 충분히 강합니다** — 111개 테스트, 동치성 1e-15,
PIT look-ahead 차단, 2026-07-23 확정 판정 재현, 용량 역산 같은 건 전부
실제로 검증된 것들입니다.
"성과 수치는 판정 원장 확정 후 산출"이라고 말하는 게, 못 지킬 숫자를
띄우는 것보다 훨씬 신뢰를 얻습니다.

### B. 화면 전체에 '예시' 라벨을 단다 (1시간)

모든 성과 화면 상단에 눈에 띄는 배너를 답니다:

> ⚠️ **예시 데이터** — 아래 수치는 합성 시나리오 기반 UI 시연이며 실측
> 결과가 아닙니다. 종목명은 화면 구성을 위한 예시 배치입니다.

그리고 차트 부제 **"PIT 스냅샷 13회 정기변경 기반 실데이터 시뮬레이션"**의
**"실데이터"를 반드시 지웁니다.** 이 문구 하나가 고지 전체를 무효화합니다.
가능하면 실제 회사명을 가상 라벨로 되돌리는 편이 안전합니다 —
"삼성전자 HBM 노출도 42%"는 실명이 붙는 순간 사실 주장이 됩니다.

### C. 확정 단면 범위 안에서만 실측으로 교체한다

2026-07-23 후보 33종목의 횡단면 판정·비중 재현은 완료했습니다. 이 결과는
해당 기준일 구성 화면에만 사용하며 시계열 성과로 확장하지 않습니다. 연속
사업연도가 확보된 구간만 백테스트하고, 없는 연도는 보간하거나 현재 판정을
복사하지 않습니다.

## 나머지 항목은 정확합니다

정리해 주신 2·3·4·5번은 제 검증 결과와 일치합니다.

- **2번 PR/TR** — 정의 정립, 병행 산출, 동치성(2.56e-15) 모두 맞습니다.
- **3번 Capping** — 47.66% → 25.00% 실증, 버킷 드리프트는 위원회 사안,
  정확합니다.
- **4번 Capacity** — 100.0 / 33.3 / 3.0 거래일 역산, ADV60 하한 상향
  제언까지 맞습니다. 다만 화면의 ADV60 값 자체는 아직 수집 전이므로
  "가정값"이라고 표기해야 합니다.
- **5번 생존편향** — 방향(Upward) 고지 맞습니다. 크기는 미측정으로
  두시는 게 정확합니다.

**설계와 논리는 탄탄합니다. 문제는 숫자를 채운 방식 하나입니다.**
그 하나가 나머지 전부의 신뢰를 끌어내릴 수 있어서, 발표 전에 반드시
정리하시길 권합니다.
