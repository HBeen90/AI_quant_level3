## 1. 파트2 조문 문서가 레포에 없습니다 (노민수님)

### 무엇을 발견했나

규칙 C(위성군) 3요건이 **어디 있는지** 찾다가 확인했습니다. 결론부터
말씀드리면 **기준은 잘 문서화돼 있습니다.**

`HBM지수.pdf`(v2) 제1부에 이렇게 있습니다.

```
규칙 C — 위성군 ... 아래 세 요건을 모두 충족할 때만 편입한다.
  ① 메모리 반도체향 매출 비중 ≥ 70%
  ② TSV·하이브리드본딩·고단 적층 등 HBM 고유 공정 귀속 매출을 문서로 확인
  ③ 지수위원회 확인 절차 통과
  [확정] 위원회는 ①·②의 문서 충족 여부만 확인한다. 선정·배제 재량은 없다.
```

v1(`HBM지수_내파트_확정규칙_및_공유사항.pdf`)과 **글자 단위로 같습니다.**
정원 폐지 개정에서도 손대지 않은 안정된 조문입니다.

### 그런데 이 PDF 가 레포에 없습니다

레포에 등재된 PDF 는 두 개뿐입니다.

```
evidence/source_docs/hbm_judgment_values_33_20260723.pdf   (판정값 33종목)
evidence/source_docs/hbm_judgment_result_20260723.pdf      (종목별 근거)
```

조문 전문이 담긴 v1·v2 와 `HBM지수_유동시총_산정근거_20260723.pdf` 는
버전 관리 밖입니다.

### 왜 문제인가

**심사에서 "그 근거 문서를 보여주십시오"에 응할 수 없습니다.**

레포 문서로 말할 수 있는 것과 없는 것이 갈립니다.

| 말할 수 있다 (판정값 PDF) | 말할 수 없다 (미등재 문서에만) |
|---|---|
| 세 요건이 존재하고 동시 충족이 조건 | ② 를 **예시형**으로 읽는 근거("등") |
| 판정원장 3컬럼으로 집행됨 | 위원회가 **재량을 갖지 않는다**는 `[확정]` |
| | 위성군 **순위 기준**(HBM관여점수) |
| | 실링 기준(버킷 대비)의 산술적 근거 |
| | 계산순서 9단계 · 폭포/희소/퇴화 조항 |

특히 마지막 두 개가 아픕니다. **백테스트에서 앵커가 85% 를 흡수하는 근거가
v2 의 희소 조항**인데, 그 문서가 없으면 "왜 40/60 이 안 지켜지나"에
"규칙이 그렇게 정해져 있습니다"라고 답할 수가 없습니다.

### 부탁드리는 것

`docs/` 에 세 파일을 등재해 주시면 됩니다.

```
HBM지수.pdf                                  (v2, 정원 폐지 반영)
HBM지수_내파트_확정규칙_및_공유사항.pdf         (v1, 정원제)
HBM지수_유동시총_산정근거_20260723.pdf          (FF 산정 근거)
```

**v1 도 필요한 이유**를 덧붙입니다. v1→v2 변경 자체가 논거이기 때문입니다.

| | v1 | v2 |
|---|---|---|
| 재배분 (7) | 같은 군 미실링 종목에만 | 폭포 3순위 — 같은 군 → 다른 비앵커 군 → **앵커 흡수** |
| 조항 | 없음 | **희소·퇴화 조항 신설** |

v1 규칙이라면 초과분이 갈 곳이 없어 조용히 증발했을 겁니다(v2 문서가
"앵커2+핵심1+위성1 구성에서 합계 73%로 종료"라는 예시를 답니다). 두 판본이
함께 있어야 "앵커 흡수는 합계 100% 보장을 위해 **의도적으로 도입**한 장치"
라는 설명이 문서로 성립합니다.

파일명은 기존 두 PDF 처럼 ASCII 로 정규화하는 게 좋겠지만, 그건 노민수님이
정하시는 게 맞습니다. `.gitignore` 가 `evidence/*` 를 막고 있으니 `docs/` 가
적절합니다.

### 안 하면

위원회 안건 1 이 성립하지 않습니다. 인용할 수 없는 문서를 근거로 조문을
방법론 정본에 옮길 수는 없으니, **등재가 이식의 선행 조건**입니다.

## 2. `index_calc.py` 가 정원제 12종목 전제입니다 (김인서님)

### 무엇을 발견했나

`src/index_calc.py` docstring 이 이렇게 남아 있습니다.

```
최종 구성종목 12개 (앵커2·핵심7·위성3) — 2.2.2/2.3 담당자 결과물 (3.1 표)
```

2026-07-22 정원 폐지가 반영되지 않았습니다.

### 코드는 정상입니다

동치성 테스트(`test_index_calc_equivalence.py`)가 7종목 → 6종목 축소를
통과하므로 **가변 종목 수로 잘 동작합니다.** 주석만 낡았습니다.

### 왜 문제인가

심사자가 코드를 열면 첫 화면이 이 주석입니다. "정원 폐지했다면서 코드는
12종목이라고 적혀 있는데요"가 나오면, 실제로는 문제없는데 설명에 시간을
씁니다. **문서-구현 불일치는 이 프로젝트가 가장 많이 지적받은 유형**이기도
합니다.

### 부탁드리는 것

docstring 한 문단만 고치시면 됩니다.

```
받는 것: 최종 구성종목 (규칙 기반 가변 — 종목 수는 산출 시점에 규칙이 정한다.
        2026-07-22 정원 폐지. 2026-07-23 확정 구성은 7종목)
```

`__main__` 데모의 12종목 예시는 **그대로 두시는 게 낫습니다** — 방법론 3.3
손계산 예시(1015.40)와 대조하는 검증이라 숫자를 바꾸면 그 검증이 깨집니다.
"데모는 방법론 3.3 예시 데이터이며 현행 구성이 아니다" 한 줄만 붙이면
충분합니다.

## 3. `universe.py` 가 빈 파일입니다 (임효빈님)

### 무엇을 발견했나

파이프라인 도식은 `universe.py → selection.py → weighting.py → ...` 인데,
`src/universe.py` 는 **0바이트**입니다. 기초 유니버스 필터(시총 350억 ·
ADV60 10억 · 상장 3개월 · 유동비율 10%)는 `analysis/build_pit_snapshots.py`
의 `screen()` 함수(248행)에 구현돼 있습니다.

### 기능은 정상입니다

`screen()` 이 `eligible` 열과 탈락사유를 만들고, fail-closed 4중 관문까지
들어가 있습니다. **파일이 비어 있을 뿐 필터는 동작합니다.**

### 그리고 위치가 합리적입니다

기초 필터는 **그 심사일의 시총·거래대금**을 요구하는데, 그건 PIT 스냅샷
생성 시점에만 알 수 있습니다. 필터를 별도 모듈로 분리해도 스냅샷 생성기가
그걸 호출해야 하므로 결국 같은 자리에서 돕니다.

### 왜 문제인가

**"유니버스 필터는 누가 구현했나요? 파일이 비어 있는데요"** 가 나올 수
있습니다. *"다른 파일에 있습니다"* 로 끝내면 약하고, **왜 거기 있는지**가
답이어야 합니다.

### 부탁드리는 것 — 세 선택지

| 안 | 내용 | 비용 |
|---|---|---|
| **A (권고)** | `universe.py` 를 지우거나, 도식 표기를 "기초 유니버스 필터 = `build_pit_snapshots.screen()`" 으로 변경 | 코드 변경 0 |
| B | `screen()` 을 `universe.py` 로 이관하고 `build_pit_snapshots` 가 호출 | 스냅샷 재생성 필요 |
| C | 그대로 둠 | 대시보드에 "빈 파일 0%" 가 계속 표시됨 |

파트3 쪽 대시보드 표기는 A안으로 이미 정정해 뒀습니다(각주에 "필터가
심사시점 시장 데이터를 요구하므로 스냅샷 생성과 같은 자리에서 돈다"는
이유까지 적었습니다). 다만 **담당 이관 자체는 임효빈님 파트라 파트3 가
단독으로 정할 일이 아니어서** 확인을 부탁드립니다.

## 4. `methodology.md` 가 존재하지 않는 7.3 을 참조합니다 (김인서님)

### 무엇을 발견했나

`docs/methodology.md` 는 **5장에서 끝나는데** 7.3 을 4회 참조합니다.

| 위치 | 참조 문구 |
|---|---|
| 3장 수시변경 (L116) | "7.3 방법론 종료 절차로 이관" |
| 3장 버퍼룰 (L142) | "방법론 개정 절차(7.3)로만 재상정" |
| 3장 적합도 모니터링 (L149) | "7.3 개정 절차로 별도 상정" |
| 5장 유지 임계값 (L233) | "방법론 개정 절차(7.3)로만 변경" |

`README.md` 도 동일 참조 4회입니다(README 는 6·7장이 있으나 7장이
「벤치마크 실행 경계」라 7.3 이 개정 절차가 아닙니다).

### 왜 문제인가

**끊긴 참조가 8곳**입니다. 그리고 그 8곳이 전부 "이 규칙은 아무나 못 바꾼다"는
**거버넌스 문장**입니다. 참조가 끊겨 있으면 "회차별 재량 조정 금지"의 근거가
없는 셈이라, 재현성 논거가 약해집니다.

### 이미 초안이 있습니다

`docs/methodology_governance_chapter_draft_20260729.md`(v2)가 장 구성
개편안까지 만들어 뒀습니다.

```
README.md      : 6장 최신화 → 7장 「방법론 거버넌스」 신설
                 → 기존 「7. 벤치마크 실행 경계」를 8장으로
methodology.md : 6장 「판정 원장 실행 경계」 신설 → 7장 「방법론 거버넌스」 신설
```

이 개편안을 쓰면 **본문 "7.3" 참조 8곳이 한 글자도 수정 없이 유효해집니다.**

### 부탁드리는 것

조문 소유가 김인서님이므로 초안을 검토·수정해 방법론에 반영해 주시면
됩니다. 위원회 1차 안건으로 함께 올릴 예정입니다.

## 5. 삼성전자 메모리향 표기가 충돌합니다 (노민수님)

### 무엇을 발견했나

판정값 PDF 20종목을 FINAL 원장과 대조했더니 **불일치가 2건**입니다.

| 종목 | 항목 | 판정값 PDF | FINAL 원장 |
|---|---|---|---|
| 삼성전자 | 메모리향 | **0.55** | **0.31** |
| 인텍플러스 | HBM노출도 | **0.02** | **0.00** |

### 원장이 맞습니다

종결기록 2항이 "삼성전자 `mem_ratio=0.31`, 인텍플러스 `hbm_exposure=0.00`
을 정본으로 삼는다"고 명시했습니다. 그리고 **판정값 PDF 자신이 그 방향을
예고했습니다** — §3 에 "초안 0.31 · 본 확정값 0.55"라 적고 **"초안이 더
정확할 수 있음 — 전사 매출에 스마트폰·TV·디스플레이가 포함되므로 메모리
단독은 30%대가 타당"** 이라는 단서를 달아 두셨습니다. 그 단서대로 됐습니다.

### 판정 결과는 안 바뀝니다

삼성전자는 규칙 0(앵커)이라 메모리향을 보지 않습니다. 인텍플러스는 두 값
모두 규칙 A·C 미달이라 미편입이 같습니다. **지수 구성·수치에 영향 없습니다.**

### 왜 그래도 정리해야 하나

발표에서 판정값 PDF 와 원장을 나란히 인용하면 **같은 값이 0.55 와 0.31 로
두 번 나옵니다.** 심사자가 "어느 쪽이 맞습니까"를 물으면 설명은 되지만,
안 물어도 되는 질문입니다.

### 부탁드리는 것

판정값 PDF 에 정정 표시를 한 줄 넣거나(재발행이 부담이면 `docs/` 에 정정
메모 한 장), 발표 자료에서 그 PDF 의 해당 값을 인용하지 않으시면 됩니다.
어느 쪽이든 노민수님 판단입니다.

## 정리 — 우선순위 제안

**1과 4가 급합니다.** 둘 다 위원회 1차 안건의 선행 조건이고, 심사에서

궁금한 점이나 제 진단이 틀린 부분이 있으면 알려주세요. 특히 3번(유니버스
필터 위치)은 파트3 가 밖에서 본 것이라 사정을 잘못 이해했을 수 있습니다.
