# 2부. 발견한 결함 3건

전부 **죽지 않고 그럴듯한 값을 내던** 유형이다. 공통점은 fail-closed 원칙의
구멍이라는 것이다.

## 2-1. 규칙 C 완화 대상이 문자열에 결합돼 있었다 (가장 컸다)

`rule_c_sensitivity.py` 가 완화 대상을 `RULE_C_UNMET = "공정/위원회 미확인"`
**문자열로** 골랐다. 위원회 안건 1-4 로 표기가 정정된 스냅샷에서는 대상을
하나도 못 찾고도 예외 없이 진행해, 등록 클레임 수치가 조용히 붕괴했다.

| | 문서·위원회 안건 | 표기 불일치 상태 |
|---|---|---|
| CAGR 차이 | **-13.50%p** | -8.04%p |
| 정기변경 평균 종목수 | 11.00 | 7.875 |
| 최종레벨 차이 | -40.7% | -26.3% |

**조문 초안 §2 가 "표기 하나가 감사 결론을 바꿀 수 있다"고 경고했는데, 그
경고를 쓴 도구 자신에게 일어났다.** 3-1(지난 세션)은 사람이 문자열을 오독한
것이고 이번은 도구가 문자열에 결합된 것이다 — 같은 뿌리, 다른 층.

조치 세 가지.

1. `RULE_C_UNMET_LABELS` 목록으로 두고 신·구 표기를 모두 인식
2. **표기 세대가 섞이면 중단**(`check_label_generation`) — 섞인 스냅샷의
   측정값은 어느 조문 상태의 값인지 말할 수 없다
3. 완화 대상이 전 회차 0건이면 **0 을 결과로 보고하지 않는다**

회귀 테스트 `tests/test_rule_c_labels.py` 9건으로 봉인했다. 그중 하나가
"앞 5개 신 표기 + 뒤 8개 구 표기"라는 실제 상태를 재현해 중단을 확인한다.

## 2-2. 스냅샷 13개가 3세대 섞여 있었다

파일 수는 13개라 겉으로는 완성이고 대시보드도 100% 로 표시한다. 수정시각이
갈렸다 — 08-01 19:45(5개) · 07-31 20:19(6개) · 07-31 05:34(2개). 중단된 실행이
앞 5개만 덮은 것이다.

지수 레벨에는 무해했다(레벨 20,881.52 재현). `탈락사유` 는 사유 문자열이고
`eligible` 판정은 동일하기 때문이다. **그러나 2-1 의 도구는 직접 오염됐다.**

해소 경위를 정직하게 적는다 — CP949 작업 전 `git stash push` 가 수정된 5개를
되돌려 **우연히** 단일 세대로 복귀했다. 계획된 조치가 아니었다. 재실행 후
13회차 전부 `공정/위원회 미확인` 단일 세대이며 CAGR 차이 -13.50%p 가
재현된다. 사유 표기 정정은 **미적용 상태로 일관**되며, 위원회 안건 1-4 로
전량 재생성 시 함께 처리한다.

## 2-3. 캡 이벤트 제수 동치성 테스트가 브랜치에 없었다

엔진(`src/index_calc.build_index_series`)은 갖춰져 있는데, 캡 경로가 정기와
동치이고 캡 당일 무점프인지 검증하는 테스트가 r11 셀프감사 번들에만 있고
`feature/backtest` 로 머지되지 않은 상태였다(HEAD `ae56bf9` 확인).

실측 캡이 68건이고 회전율의 60.5% 가 거기서 나온다. "캡 적용일에 지수가 튀지
않는다는 걸 어떻게 아나"에 답할 근거가 없었다.

번들에서 **함수만** 이관했다(파일째 덮으면 로컬의 어댑터 fail-closed 강화가
날아간다 — 3부 참조). 4건 통과.

## 2-4. CP949 콘솔 게이트 위반 4파일

레포 자체 게이트(`test_claims::test_python_sources_are_cp949_compatible`)가
실패했다. 원인은 대시 문자다 — 프로젝트 관례는 **U+2015(`―`)** 인데 U+2014
(`—`)·U+2212(`−`)가 섞였다. 둘 다 CP949 에 없어 팀 PowerShell 기본 콘솔에서
직접 실행하면 죽는다. 관례대로 치환했다.

# 3부. 작업 중 저지른 오류 1건

## 3-1. 정본 파일을 구버전으로 덮었다

`tests/test_index_calc_equivalence.py` 의 CP949 수정본을 만들 때, 원본으로
**세션에 업로드된 사본**을 썼다. 그 사본이 HEAD 보다 14줄 짧은 구버전이어서
어댑터의 fail-closed 강화가 함께 사라졌다.

| | HEAD 정본 | 덮어쓴 것 |
|---|---|---|
| `to_reconstitution_events` | 종목별 `ff_mcap` 결측·비양수·비유한 검사 후 누락 티커 명시 실패 | 검사 없이 `reindex` 통과 |
| `test_adapter_rejects_missing_fmc` | 일자 + **종목별** 2단 검증 | 일자만 |

`git diff --stat` 이 잡았다 — 대시 1자 수정인데 28줄 변경·순감 14줄이었다.
`git checkout` 으로 복구했다.

**중간 진단도 틀렸다.** 처음에 "캡 동치성 테스트가 사라졌다"고 판단했으나
그 테스트는 HEAD 에도 없었다(2-3 이 그 사실이다). r11 번들과 브랜치를 같은
계보로 착각한 것이다.

**교훈 두 개.** ① 인코딩만 고치는 작업이라도 **diff 규모가 예상과 맞는지**
확인해야 한다. 대시 n 자 수정은 2n 줄 변경이어야 한다. ② 번들과 브랜치는
계보가 다르다 — 어느 쪽이 정본인지 `git show HEAD:` 로 확인하고 시작할 것.
