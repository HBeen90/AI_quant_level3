## 안건 1. 규칙 3(위성군) 3요건 조문 신설

**현황.** 코드(`src/selection.py`)는 위성군을 세 요건의 결합으로 판정한다.
방법론 규칙 3은 정성 서술("HBM 귀속 매출 분리가 어려운 전공정 장비·소재
기업")뿐이며 **판정 기준이 없다.**

```
① 메모리향 매출 비중 70% 이상        (mem_ratio)
② HBM 고유공정 귀속 매출 문서 확인    (process_confirmed)
③ 지수위원회 확인 절차 통과           (committee_ok)
```

**왜 지금인가.** 요건 ②③을 해제하면 CAGR이 **64.54% → 51.03%(−13.50%p)**,
최종레벨 −40.7%다. 문서화되지 않은 규칙이 성과의 상당 부분을 만들고 있다.
"위성군은 어떤 기준으로 뽑았습니까"에 답할 문서가 현재 없다.

**결정 사항 4건**

| | 항목 | 쟁점 |
|---|---|---|
| 1-1 | 요건 ① 임계값 70% 확정 | 코드 상수 `SAT_MEM_TH` 를 조문값으로 승격 |
| 1-2 | 요건 ② "HBM 고유공정" 열거가 **폐쇄형인가 예시형인가** | 폐쇄형=신규 공정마다 조문 개정 / 예시형=판정 재량 발생, 재현성 약화. **현재 코드는 사실상 예시형** |
| 1-3 | 요건 ③ 위원회 무재량 서술 승인 | 위원회는 ①②의 문서 충족 여부만 확인 |
| 1-4 | 사유 표기 정정 시점 | `공정/위원회 미확인` → `규칙 C 요건②③ 미충족`(코드 변경 · 스냅샷 재생성 동반) |

**1-2가 실무적으로 가장 중요하다.**

**비용.** 조문 개정만. 지수 계열·수치 불변.
**근거 문서.** `docs/rule_c_clause_draft_20260731.md`

## 안건 3. 40/60 버킷 규정 — 실질 결정

**현황.** 방법론은 "앵커 40% / 비앵커 60%"라고 적었으나, **13회 정기변경 중
40%가 실현된 것은 1회**다. 나머지 12회는 희소 조항이 발동해 앵커가 85% · 67% ·
64%에서 출발했다. 괴리의 **92%가 구조 성분**이므로 리밸런싱 주기 조정으로는
해결되지 않는다.

| 정기변경 | 앵커 실현 | 회차 |
|---|---:|---:|
| 2020-06 ~ 2023-12 | **85.0%** | 8 |
| 2024-06 ~ 2024-12 | **67.0%** | 2 |
| 2025-06 ~ 2025-12 | **64.0%** | 2 |
| 2026-06 | **40.0%** | 1 |

### 선택지

| | 안 A — 가중 규칙 개정 | 안 B — 조문 문구 정정 |
|---|---|---|
| 내용 | 위성 합계 상한(18%) 상향 또는 핵심군 최소 종목 수 요건화 | 40%를 "수용량 제약 하의 목표치"로 명시, 희소 조항을 본문으로 승격 |
| 얻는 것 | 40/60이 실제로 성립 | **코드 변경 0** · 실측과 문서 일치 |
| 잃는 것 | 테마 순도 논거 약화(위성 상향) / 후보 없는 기간 산출 불가(핵심군 요건, 표본 8회 해당) | "앵커 40%"라는 간명한 설명 포기 |
| 비용 | **백테스트 전량 재실행 + 게이트 재승인** | 조문 개정만 |

**안 C(버킷 밴드)는 보류를 확정한다.** 밴드 기준점(85%)이 개별 캡이 지탱할 수
있는 최대치(앵커 2종목 × 30% = 60%)와 **산술적으로 양립하지 않아** 회전율이
**15.4배**가 된다. 도달 가능한 회차는 13회 중 1회뿐이다.

### 함께 상정할 실측 발견

**월말 캡이 5종목 미만 구성에서 퇴화한다.** 상한 절삭이 아니라 균등비중
복원으로 동작하며, 임계는 5종목이다(4종목도 64.5% 퇴화). 실측 캡 68건 중
**61건이 그 구간**이고, 전체 회전율의 **50.5%가 집중도를 낮추지 못했다.**
3종목 캡 집행일 56일 전부에서 앵커 버킷이 정확히 2/3, 편차 0.00e+00.

현행 하한 5종목은 **캡이 상한으로 작동하기 위한 최소 조건과 정확히 일치**한다.

**작성자 의견.** 안 B 권고. 안 A는 지수 성격을 바꾸는 결정이라 재실행 일정이
필요하고, 현재 가장 큰 위험은 규칙이 틀린 것이 아니라 **문서와 구현이 다른
말을 한다는 것**이다.

**근거 문서.** `버킷규정_개정안.md` · `analysis/cap_feasibility.py` ·
`analysis/bucket_band_turnover.py`

## 안건 4. 후보발굴 사전 승인

**현황.** 전시장 스크린 계약과 구현은 완료됐으나, 계약 §8이 세 가지를 미결로
남겼다.

| | 항목 | 기안 |
|---|---|---|
| 4-1 | 키워드 사전 `kw_v1` | HBM 계열 5개 · 공정 계열 7개(TSV·TC본딩·하이브리드본딩·MR-MUF 등) |
| 4-2 | 발굴 임계값 | `hbm_hits >= 5` |
| 4-3 | 전시장 열거 원천 / 실행 주기 | pykrx vs KRX 상장목록 API · 매 심사시점 필수 여부 |

**승인 전에는 발굴 결과를 확정으로 인용할 수 없다.** 다만 승인이 없어도
"조사했고 현 시점 누락 0건"은 말할 수 있으므로 급하지 않다.

**한계 고지.** 전 상장종목의 과거 시점 사업보고서 전수 재조회는 현실적으로
불가능하다. v1은 **현 시점 1회 스크린**이며, 과거 구간은 후보군 고정 상태이고
편향 방향이 상향일 가능성을 별도 고지한다.

**근거 문서.** `docs/candidate_discovery_contract.md` ·
`analysis/candidate_discovery.py`
