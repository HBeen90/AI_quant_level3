# HBM 지수 데이터 인계 계약

## 목적

판정, 비중 산정, 리밸런싱과 백테스트가 동일한 시점의 입력을 사용하도록
파일별 책임과 필수 메타데이터를 고정한다. 숫자만 일치하는 재현과
시점·원천까지 추적되는 재현을 구분한다.

## 1. 후보 판정 스냅샷

후보 33종목에서 편입 종목을 순방향 재생할 때 사용하는 입력이다.
선정기준일마다 한 파일 또는 명시적인 `selection_date` 열을 사용한다.

| 필수 열 | 계약 |
|---|---|
| `selection_date` | 해당 행의 심사 기준일, 전 행 동일 |
| `종목명` | 공표 종목명 |
| `코드` | 6자리 문자열 |
| `유형` | `메모리제조` 또는 파트2 표준 유형 |
| `유동시총` | 선정기준일 현재 값, 양수 |
| `HBM양산` | 엄격 Boolean |
| `HBM노출도` | 0~1, 규칙 A 판정값 |
| `메모리향비중` | 0~1, 규칙 C 판정값 |
| `HBM공정확인` | 엄격 Boolean |
| `위원회확인` | 엄격 Boolean |
| `evidence_asof` | 판정에 사용한 최신 공개자료 기준일 |
| `evidence_source` | DART 접수번호 또는 원천 식별자 |

사전 유니버스 필터 결과를 별도 파일로 전달하면 티커와
`selection_date`가 이 스냅샷과 정확히 일치해야 한다.

## 2. 구성종목 비중 인계

`weighting.allocate`와 지수 산출 파트가 소비하는 최종 횡단면 입력이다.

| 필수 열 | 계약 |
|---|---|
| `코드` | 6자리 문자열, 중복 금지 |
| `종목명` | 공표 종목명 |
| `bucket` | `anchor`, `core`, `satellite` |
| `weight` | 0~1 공표 비중 |
| `ff_market_cap` | 비중 산정에 실제 사용한 유동시가총액 |
| `selection_date` | 심사 기준일 |
| `ff_market_cap_asof` | FMC 가격·주식수·유동비율의 기준일 |
| `ff_market_cap_source` | KRX·pykrx 등 원천과 산식 버전 |
| `float_ratio_asof` | 유동비율 기준일 |

현재 `구성종목_인계_20260723.csv`는 비중 순방향 재현에는 충분하지만
마지막 네 메타데이터 열이 없다. 제공자가 확인하기 전에는 값을 추정해
채우지 않는다.

## 3. 실행 메타데이터

결과 보고서에는 입력 파일 SHA-256, 코드 커밋 SHA, 방법론 버전, 실행일,
공표 비중 정밀도와 허용오차, `weighting.verify` 결과를 기록한다.

## 4. 완료 판정

- **비중 산정 재현 완료**: 확정 구성과 FMC에서 공표 반올림 범위 내 비중 재현
- **선정 판정 재현 완료**: 전체 후보 PIT 스냅샷에서 동일 종목·군 재현
- **시계열 검증 완료**: 복수 정기변경에서 회전율·비용·경보 발동률 산출

세 상태를 하나의 "전체 검증 완료"로 합쳐 표현하지 않는다.
